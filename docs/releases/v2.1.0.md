FCM Guard 2.1.0 — keeps working when HyperOS takes its permission away.
FCM Guard 2.1.0：HyperOS 收回权限后也能继续守护。

> **From 2.0.x: install over it directly.** It is signed with the same release key.
> **从 2.0.x 升级：直接覆盖安装**，签名密钥相同。

**Fixes / 修复**
- **Modify system settings switched off overnight:** on some HyperOS 4 China builds this permission was found turned off in the morning, so Google Play services fell off the whitelist and pushes stopped. FCM Guard now watches the permission, re-checks on unlock, screen-on, network change, charger connection and boot, and shows a notification that opens the grant screen. A one-time `adb shell pm grant com.reed.fcmguard android.permission.WRITE_SECURE_SETTINGS` makes the repair independent of that switch (README: *If HyperOS turns off Modify system settings*).
  部分 HyperOS 4 国行版本会在夜间关闭“修改系统设置”权限，导致 Google Play 服务被移出白名单、推送中断。FCM Guard 现在会监听该权限，在解锁、亮屏、网络变化、接通充电器和开机时复查，并弹出通知直达授权页。执行一次 `adb shell pm grant com.reed.fcmguard android.permission.WRITE_SECURE_SETTINGS` 后，修复不再依赖该开关（见 README）。
- **Repair no longer gives up early:** it now attempts the write and verifies it by reading the value back, instead of trusting the permission check alone.
  修复不再因权限检查而提前放弃：会尝试写入并回读校验。

**New / 新增**
- **Night protection (HyperOS 4), on by default:** also keeps Google Play services on HyperOS's game-download freeze exemption list (`com.miui.game.allowlist`), which HyperOS 4 still honours at night (23:00–08:00) when it ignores the no-restrict whitelist. Turning it off removes the entry if FCM Guard added it.
  **夜间保护（HyperOS 4，默认开启）**：同时把 Google Play 服务加入游戏预下载免冻结名单，HyperOS 4 夜间（23:00–08:00）忽略无限制白名单时仍遵守该名单。关闭时会移除由 FCM Guard 添加的条目。
- **Event log:** permission changes, repairs and how the previous process ended (force stop, freezer, low memory…), with Copy and Clear.
  **事件日志**：记录权限变化、修复以及上一个进程的结束原因，可复制、清空。
- The reconnect kick also sends `GCM_RECONNECT` to Google Play services.
  重连请求同时发送 `GCM_RECONNECT`。
- The 30-minute fallback is now a non-wakeup alarm, so it also restarts the service after HyperOS kills the process. It never wakes a sleeping phone.
  30 分钟兜底改为不唤醒设备的闹钟，进程被杀后也能重启服务；不会唤醒休眠手机。
